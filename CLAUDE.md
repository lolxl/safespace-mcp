# SafeSpace MCP — Project Context

## Project Framework Info

- **My idea (NORTH STAR, reframed 2026-06-06 — `docs/safety-gateway-thesis.md`, Q1–Q8 LOCKED)**: SafeSpace is **the AI safety gateway for an agent's external surface** — a provider-agnostic safety ENVELOPE (sanitize / untrusted-content wrapping / scope·tier·burst·recipient gates / Autonomy Hardening F1–F6 / `run_id` session forensics / `SecretBackend`) between an AI agent and **any source it touches**. **The envelope is the product; sources are connectors behind it.** Google Workspace (Gmail + Drive + Docs + Calendar + Contacts + YouTube + Tasks + Sheets + Slides + Forms) is the **flagship reference connector** (`source: "google-workspace"`, `authModel: "oauth"`); future additions are evaluated as connectors-by-class — **A. OAuth-account** (Google; Threads/IG/X) · **B. service-token** (Telegram Bot / LINE OA — one token in `SecretBackend`, no OAuth) · **C. keyless** (web-fetch / filesystem — pure inbound-sanitize). The enabling refactor (re-cut per the 2026-06-06 architecture review) = a `Source` seam built on a **`Credential` discriminated union** (`oauth`/`service-token`/`none`) + `CredentialResolver`/`Authorizer` strategies (NOT an `authModel` enum the choke point branches on); the OAuth machinery (`V1_SCOPES`/consent/`SCOPE_HIERARCHY`/`requiredScopes`) demotes to the google-workspace source's strategy impls. This is **axis 1 (sources)**, decoupled from **axis 2 (Model B multi-operator)** — adding sources does NOT require Model B. The Source seam (Phase A→C) and the Model B operator-auth arc both shipped; see `docs/CHANGELOG.md`.
- **How serious I am**: **Open-source + genuine multi-user collaborative use** (e.g. several people co-managing a shared YouTube channel through one deployment). Owner-decided 2026-05-31.

## Security policy layers (still authoritative)

- **`SAFESPACE_TIER=read|write|share`** (read default) — proxy filters `tools/list` at startup; no per-call escalation. v1.38 (BLOCKER 3): in-handler defense-in-depth re-checks read a per-call `ctx.tier` resolved once at the orchestration choke point (= the process tier under Model A); the `tools/list` filter + per-call proxy gates stay process-global
- **`SAFESPACE_CONNECTORS`** (v1.127, `policy/connector-toggle.ts`) — the SECOND exposure axis, orthogonal to tier and **intersected** with it (narrowing-only: a listed connector can never carry a tool past its `min_tier`). Comma-separated tokens = the 11 non-Google `SOURCES` ids ∪ 10 Google sub-services (derived by tool-name prefix, since google-workspace is ONE source worth ~39k of the ~52k share-tier schema cost) ∪ `google-workspace` as an alias for all ten; `_`→`-` folded, case-insensitive. Enforced at BOTH `tools/list` and `tools/call` (the list is advisory to the client), collapsing into the existing `tool_not_found` — no new error code, no config oracle. **UNSET = all connectors on = byte-identical** — the DELIBERATE inverse of the deny-default egress allowlists, because unset-means-deny would silently strip every tool on upgrade. Unknown token → `validateConnectors()` refuses to start (in `proxy.ts`'s guarded sequence, never at module eval); an UNMAPPED tool is fail-safe (always exposed) with a sentinel test making the gap red in CI. Motive is **context cost on non-lazy clients** (Codex / Grok / Antigravity / Cursor — Claude Code defers schemas and pays nothing; measured: share tier 130 tools/~51.9k tok → 43/~15.3k with `gmail,calendar,github`). **NOT covered — this axis gates the AGENT'S TOOL SURFACE and nothing else** (4 gaps, all documented in the module header + `.env.example` + `docs/DEPLOY.md` + CARRY-FORWARD 5–7): ① `safespace exec` bypasses it, as it already bypasses tier ② it does NOT shrink the OAuth scope union (`computeScopeUnion` unions over the whole registry — narrows the agent's reach, not the token's) ③ it does NOT close the inbound webhook listener — that is `SAFESPACE_WEBHOOK_PORT` alone; omitting `webhook` hides `inbox_read` but the public port stays bound and callbacks still reach the durable inbox (**the widest gap** — that is SafeSpace's only unsolicited public surface) ④ it does NOT stop the internal contacts name→email lookup under `SAFESPACE_RECIPIENT_ALLOW_CONTACTS` (the `contacts_*` tools ARE hidden and blocked; the helper call is not)
- **Recipient allowlist** (v2.2, env-var two-layer): `SAFESPACE_RECIPIENT_ALLOW` (persistent) + `SAFESPACE_RECIPIENT_ALLOW_EXTRA` (shell-only). Gates `drive_share_file (share_type=user) target_email` + `gmail_send to/cc/bcc` + `gmail_create_draft to/cc/bcc` (v1.43, all-or-nothing; a draft is a latent send). Rejected recipients HMAC-SHA256 hashed in `audit.jsonl`. Optional `SAFESPACE_RECIPIENT_ALLOW_CONTACTS="true"` opt-in (strict-truthy lowercase) for name→email resolution; resolved emails STILL pass through this allowlist (lookup augments INPUT shape, never bypasses OUTPUT gate). v1.80: the self-send exemption is partitioned by the calling operator's `allowedAccounts`
- **Drive whitelist** (v2.1, `drive-whitelist.json`): folder-subtree + file-ID allowlist at `drive_share_file` boundary. Walks parents (`MAX_WALK_DEPTH=10`), per-process LRU cache. `drive_unshare_file` bypasses unconditionally (recovery > policy)
- **Tasks-delete allowlist** (v1.39, env-var two-layer): `SAFESPACE_TASKS_DELETE_TARGETS` (persistent) + `..._EXTRA` (shell-only), `tasklist:<id>` entries. Gates `tasks_delete` ABOVE tier (opt-in tightening); **default OFF = allow** (private + tier-gated surface, opposite of the public youtube-comment deny-default). Denial → `-32030 tasks_delete_denied_by_policy` (no id echoed); fires before the SDK delete. **Gates the PERMANENT `tasks_delete` ONLY** — NOT the v1.47 `tasks_clear` (which bulk-HIDES completed tasks, RECOVERABLE, so tier alone is the floor)
- **GitHub write target allowlist** (v1.71, env-var two-layer): `SAFESPACE_GITHUB_WRITE_TARGETS` (persistent) + `..._EXTRA` (shell-only), `owner/repo` entries (case-insensitive). Gates `github_create_issue` / `github_create_issue_comment` / `github_update_issue`; **default-empty = HARD-DENY** (PUBLIC surface — mirrors the youtube-comment deny-default, the OPPOSITE of the recipient off→allow). Denial → `-32042 github_write_denied_by_policy` (no owner/repo echoed — PII-oracle defense); runs FIRST in `enforceGithubWriteEgressGates`, before per-field `outboundSanitize` (the public-surface 6-step REJECT, `-32027`) + F3a secret-shape on the body. The request body is ALLOWLIST-CONSTRUCTED (only `title`/`body`/`state`). ZERO new scope (public-repo writes ride the existing `public_repo`)
- **GitHub approve target allowlist** (v1.90, `policy/github-approve-targets.ts`, env-var two-layer): `SAFESPACE_GITHUB_APPROVE_TARGETS` (+`_EXTRA`), `owner/repo` (case-insensitive). The SEPARATE default-deny gate for the **APPROVE** event of `github_create_pull_request_review` — an APPROVE vouches for a PR and (under branch protection) can UNBLOCK its merge, a higher bar than a comment, so it has its OWN list (a repo write-allowlisted is NOT thereby approve-allowlisted; same separation as the v1.82 merge-target gate). `enforceGithubReviewEgressGates` is EVENT-CONDITIONAL: **APPROVE** → this allowlist (miss → new `-32048 github_approve_denied_by_policy`, no owner/repo echoed); **COMMENT / REQUEST_CHANGES** → the WRITE allowlist (miss → `-32042`). Then F3a secret-shape + per-field `outboundSanitize` on the `body`; request is ALLOWLIST-CONSTRUCTED (only `event`/`body`/`commit_id`). ZERO new scope (rides the existing `repo`); `doctor --posture` enumerates a `github-approve` row
- **YouTube video-metadata write target allowlist** (v1.106, `policy/youtube-video-targets.ts`, env-var two-layer): `SAFESPACE_YOUTUBE_VIDEO_TARGETS` (+`_EXTRA`), `video:<11-char-id>` entries ONLY (channel:/playlist: rejected — they'd need a pre-fetch channel-resolve = TOCTOU). The default-deny gate for `youtube_video_update` (videos.update snippet). **default-empty = HARD-DENY** (PUBLIC surface — a video title/description is the channel's most public identity text; mirrors the youtube-comment + github-write deny-default, NOT the playlist "channel-owned, no allowlist" model — owner-locked Q1). Denial → `-32052 video_target_denied_by_policy` (no video_id echoed — PII-oracle defense); checked in the handler BEFORE per-field `outboundSanitize` (`-32027`) + F3a secret-shape (the now-exported shared `enforceOutboundSecret`). requestBody is ALLOWLIST-CONSTRUCTED (snippet ⊆ title/categoryId/description/tags; `part:["snippet"]` only → privacy/status untouchable). ZERO new scope (rides `youtube.force-ssl`); `doctor --posture` enumerates a `youtube-video` row
- **X post account allowlist** (v1.115, `policy/x-post-allowlist.ts`, env-var two-layer): `SAFESPACE_X_POST_ACCOUNTS` (+`_EXTRA`), numeric X user-id entries (`^[0-9]{1,32}$`; usernames rotate → rejected). The default-deny gate for `x_post_create` (POST /2/tweets). **default-empty = HARD-DENY** (PUBLIC surface — mirrors youtube-comment/github-write). Denial → `-32056 x_post_denied_by_policy` (no id echoed); gate order LOCKED: allowlist FIRST → F3a secret-shape → `outboundSanitize` (the WIRE gets the sanitize RETURN VALUE — no TOCTOU); weighted-280 local precheck (URL=23, CJK/emoji=2) rejects over-limit text before any network. Body is ALLOWLIST-CONSTRUCTED (`{text}` only; no reply/quote). `doctor --posture` enumerates an `x-post` row
- **Filesystem read gate** (v1.75, `policy/fs-gate.ts`): DEFAULT-DENY root allowlist (`SAFESPACE_FS_READ_ROOTS`+`_EXTRA`); canonical (realpath) containment on both request and roots (symlink-safe), nearest-ancestor canonicalization → no path-existence oracle; regular-file + ≤5 MB + UTF-8 caps; `-32043 path_blocked_by_policy` / `-32044 fs_read_failed`
- **Outbound URL gate** (v1.65, `policy/url-gate.ts`): the `web_fetch` SSRF gate — scheme/port allowlist + private/reserved/metadata-IP block + DNS-rebind IP-pin + per-hop redirect re-gate + size/timeout/content-type caps; `-32036 url_blocked_by_policy` / `-32037 web_fetch_failed`
- **Sanitize pipeline** (`src/sanitize/`): zero-width strip → confusables normalize → pattern flag → truncate → `<untrusted-source-${nonce}>` wrap. Per-source `skipFields` for opaque IDs/timestamps. Per-call nonce (16 hex / 64 bits) prevents pre-staged closing-tag injection
- **Inbound formula REJECT** (`src/sheets/formula-reject.ts` + `src/sheets/homoglyph-normalize.ts`): 11-function REJECT set (IMPORTRANGE-class SSRF + phishing) post-NFKC + zero-width strip + UTS#39 Cyrillic/Greek homoglyph normalize + Default_Ignorable/bidi strip. `-32029 formula_rejected`
- **Outbound sanitize** (`src/sanitize/outbound.ts`): 6-step locked-ORDER REJECT pipeline for PUBLIC-surface text (YouTube comments, GitHub write). `-32027 outbound_sanitize_rejected`
- **Autonomy Hardening F1–F6** (`policy/`, autonomous mode via `SAFESPACE_AUTONOMOUS`): F1 universal write/delete burst caps (reads exempt; `-32032`; v1.92 **per-operator** under Model B — keyed on the resolved `OperatorContext`, Model A null → one shared sentinel bucket = byte-identical; optional per-operator `writeBurstLimit`/`deleteBurstLimit` overrides in `operators.json`, fail-loud `[1,100000]`) · F2 deny-by-default allowlists · F4 permanent-delete deny (`-32033`) · F3/F3a tainted-source + outbound secret-shape REJECT (`-32034`/`-32035`) · F5 `run_id` session-grouped audit · F6 token-at-rest hardening
- **Enforced mode** (v1.86, `policy/enforced-mode.ts`, `SAFESPACE_ENFORCED`; `docs/SOLE-EGRESS.md`): generalizes F6's refuse-to-start to a company-deployment checklist — autonomous on + non-keyfile token store (STRICTER than F6: the `SAFESPACE_ALLOW_KEYFILE_AT_REST` hatch is NOT honored) + HTTP bind ≠ `0.0.0.0`/`::`. Bootstrap exits before serving any tool, naming every failing precondition; opt-in strict-truthy (unset = Model A byte-identical). `safespace doctor --posture` reports the gates + (v1.87, `policy/egress-posture.ts`) a per-connector egress/access allowlist enumeration (`restricted (N)`/`deny-all`/`OPEN`, counts-only no-PII-echo) + (v1.88, `policy/egress-destinations.ts`) the egress-DESTINATION registry + the honest "Layer 2–4 are deployment-external" reminder. ZERO new tool/scope/error-code/audit-channel
- **Egress-destination registry** (v1.88, `policy/egress-destinations.ts`): the ONE auditable list of external hosts SafeSpace's OWN process connects to. `assertEgressHost(host, connector)` is a defense-in-depth backstop wired into the 5 socket-owned fetch chokepoints (github/notion/line/telegram/discord) — a path-injection host-escape (`api.github.com@evil.com`) or a connector bug to an unexpected host → `-32047 egress_destination_blocked` (echoes the host ONLY, never the token-bearing URL). Honest boundary: googleapis-SDK + dynamic web-fetch hosts are `declared` (audit-listed, not gatable here). Fixed code registry, no env host override
- **Tamper-evident audit hash-chain** (v1.89, `audit.ts` + `cli/audit/verify.ts`; `docs/AUDIT-CHAIN.md`): every `audit.jsonl` row carries `row_mac = HMAC-SHA256(audit-salt, prev_mac ‖ canonicalJson(row))` — edit/delete/insert/reorder of a past row breaks the chain, caught by `safespace audit verify` (exit 0/1, first offending row). HMAC-keyed by the per-install salt (outside the log) → forgery needs the salt (F6 threat model: backup/log-pipeline/lower-priv/offline). Per-process write mutex serializes the chain; tip continues across restarts. Honest boundary: no defense vs a salt-reading same-host attacker nor TAIL truncation (verify prints the tip to anchor out-of-band). Additive field (readers ignore it); legacy unhashed prefix tolerated. SINGLE-WRITER assumption (Model A/B both are)
- **Gmail label name gates**: CR/LF/NUL/NEL/U+2028/U+2029 reject, system-label blacklist, 225-byte cap
- **`gmail_modify_messages_batch` gates**: TRASH/SPAM block on add, ≤10 label IDs per side, hex ID validation, `MAX_MESSAGE_IDS_PER_BATCH=100` blast-radius guard, local dedup, `batch_too_large` (-32020)
- **Service-token egress** (LINE / Telegram / Discord / Slack / **Mattermost**): per-connector recipient allowlist + F3a secret-shape, TEXT-only payloads (no SSRF-by-proxy), token never echoed; shared hardened fetch (`handlers/service-token-fetch.ts`, timeout + body cleanup + v1.95 optional `checkBody` seam for Slack's 200-but-`ok:false` model). Slack escapes `&<>` so mention/link control sequences are inert (v1.95). **Mattermost (v1.107) — the FIRST self-hosted connector**: its host is OWNER-configured (`SAFESPACE_MATTERMOST_SERVER_URL`, validated https-only once in `auth/mattermost/base-url.ts`, private/internal hosts allowed since owner-set-not-agent-supplied), pinned by `assertEgressHost` via a new `enforcement:"configured"` egress-destination category (fail-closed when unset); `-32053 mattermost_api_failed` (`no_server_url` reason unique to it). ACCEPTED RISK: Mattermost `@channel`/`@all`/`@here` are NOT neutralized (no reliable primitive; bounded by the recipient allowlist + self-hosted deployment)
- **Multi-operator (Model B)**: Tailscale-WhoIs verified identity (non-forgeable peer IP, not a client header) → default-deny `operators.json` registry → per-operator tier + `allowedAccounts` confinement; cross-account `*_all` fan-out confined to the operator's accounts. Loopback/tailnet-only HTTP transport; stdio (Model A) is the default and byte-identical. **Per-operator F1 burst** (v1.92): the write/delete rate window is keyed per operator. **Token auth** (v1.93 A1, `SAFESPACE_AUTH=token`, `policy`-adjacent `auth/agent-token-store.ts`): an alternative off-tailnet identity source — a per-request `Authorization: Bearer` resolves (HMAC-hash → `agent-tokens.json`, hashes-only-at-rest, fail-loud, optional `--expires`) to a login that STILL passes the same default-deny registry; managed via `safespace agent-token {mint,revoke,list}`. **A2 (v1.94)** opened it off-loopback: a **per-request token re-check** (the bearer is re-resolved every request → `revoke`/expiry bites an open session; a login swap → 403 — the real anchor behind a reverse proxy, where the peer IP collapses to the proxy) + a strict-truthy **`SAFESPACE_TLS_TERMINATED`** attestation that relaxes the enforced-mode all-interfaces bind gate (the listener stays plaintext `node:http` — NO in-process TLS; front it with a TLS-terminating proxy). Tailscale mode byte-identical (no per-request WhoIs)
