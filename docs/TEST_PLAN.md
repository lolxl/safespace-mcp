N/A — this is a CLI + stdio MCP server, no HTTP UI surface. Affected surfaces instead:

- **stdio MCP surface** — what Claude Code sees over stdin/stdout (tools/list, tools/call)

- **Network** — Google OAuth + Gmail/Drive API (or remote MCP in Approach C)

## Key Interactions to Verify

### Unit layer (24 tests)

**`sanitize/index.ts` (15 tests — P1(c) core)**
1. Clean content passes through with `<untrusted-source>` wrapper, no flags
2. Each of the 3 predefined injection patterns from `sanitize/patterns.ts` gets flagged correctly (3 tests, one per pattern)
3. Zero-width char U+200B stripped
4. Zero-width char U+200C stripped
5. Zero-width char U+200D stripped
6. Zero-width char U+FEFF stripped
7. Cyrillic 'а' (U+0430) normalized to Latin 'a' (U+0061)
8. Other confusables subset normalized (sample 2-3 from Unicode confusables.txt)
9. Body at exactly 50KB passes un-truncated
10. Body at 50KB+1 truncated with marker `<truncated at 50KB>`
11. Drive file at 5MB passes
12. Drive file at 5MB+1 rejected with MCP error `file_too_large`
13. Malformed input (non-string, circular ref, BigInt, etc.) → throws → caller must fail-closed
14. Multiple patterns in same input → all flagged in order
15. Sanitize output is deterministic given same input (snapshot-able)

**`tools/with-context.ts` (3 tests — security boundary)**
1. Non-whitelisted tool name rejected with `tool_not_found` before any auth/API work
2. Sanitize throws → entire tool call fails with `sanitize_failed` MCP error; no content returned to LLM
3. Happy path: auth → API call → sanitize → audit log written → return

**`auth/refresh.ts` (2 tests — concurrency correctness)**
1. Two concurrent `refresh(email)` calls coalesce into one HTTP request (mutex assertion: `fetch` called exactly once)
2. When Google rotates refresh_token, Keychain entry updated with new refresh_token before response returns

**`auth/keychain.ts` (2 tests — crash safety)**
1. Atomic write: simulate crash between tmp write and rename → on restart, old `accounts.json` still valid
2. Corrupt `accounts.json` detected at startup → rebuild via Keychain enum (per Issue 1A)

**`tools/registry.ts` (1 test)**
1. scope union computation: given TOOL_REGISTRY with 5 tools declaring varied scopes, `computeScopeUnion()` returns deduplicated sorted set

**`errors.ts` (1 test)**
1. All 7 predefined error codes serialize to the shape `{code, message, data: {reason, recovery?}}` (snapshot test)

### Integration layer (10 tests — user flows + boundary conditions)

**First-time setup (2)**
1. `safespace consent <email>` launches browser, accepts callback, writes Keychain entry
2. `safespace consent <email>` user denies consent → clean state (no Keychain entry left behind)

**Daily use (2)**
3. `account_switch → gmail_search` uses the new account (assert correct token used)
4. Two concurrent `gmail_search` calls both succeed (assert refresh mutex kicked in if token near expiry)

**Scope change (1)**
5. Add new tool to TOOL_REGISTRY → startup detects scope mismatch → requires `--re-auth`

**Error UX (5)**
6. Keychain locked at fresh boot → `gmail_search` returns MCP error `keychain_locked` with recovery hint
7. Google API returns 429 → exponential backoff 1s/2s/4s → success on retry
8. Google API returns 429 after 3 retries → `rate_limited` MCP error with `data.retry_after_sec`
9. Refresh token invalid → Keychain entry cleaned → `refresh_token_invalid` MCP error with recovery hint
10. Tool name not in whitelist → `tool_not_found` MCP error, never touches Google

### Consent flow (2 additional security tests)

11. OAuth state parameter mismatch between request and callback → flow aborted with clear error (no token ever stored)
12. PKCE code_verifier mismatch → flow aborted, no token stored

## Edge Cases

- Keychain entry for email that no longer exists in `accounts.json` → treat as orphan, log warning, don't fail
- Concurrent `account_revoke` + `gmail_search` on same email → revoke wins; search gets clean `account_not_found`
- `audit.jsonl` write fails (disk full) → log to stderr, don't fail the tool call (audit is best-effort observability, not a gate)
- Token rotation during concurrent refresh → mutex ensures one refresh completes fully before next begins (covered by `auth/refresh.ts` test #1)
- `sanitize()` output itself contains a pattern matching `<untrusted-source>` tag → should not double-wrap (test: idempotent sanitize on already-sanitized content)

## Critical Paths (End-to-End, test first)

1. **Fresh install → first tool call** — zero state to working. If this breaks, nothing works
2. **Token auto-refresh mid-session** — most common "just works" or "mysteriously broken" path
3. **Sanitize fail-closed** — P1(c) cannot fail open. Must be E2E-verified with real pretend-adversarial input via actual MCP stdio
4. **Multi-account switch under load** — user's core differentiator; concurrent use must be correct

## LLM/Prompt Changes

None in this plan. No eval tests required.

## Baseline Metrics (establish during Step 1-6 implementation)

- Unit test count: target 24 passing
- Integration test count: target 12 passing
- Unit test runtime: under 2s total (matters for tight dev loop)
- Line coverage via `bun test --coverage`: target ≥ 85% (some handler glue code will naturally be uncovered; sanitize/auth must be 100%)
- Branch coverage on `sanitize/index.ts`: target 100%

## Regression Rule Applied

No existing code → no classical regressions. But any future change to `sanitize/patterns.ts` MUST include a new test proving the pattern is flagged. This is enforced by code review discipline, not tooling, in v1.

| Concurrent gmail_search under load (two Claude Code instances) | Integration #4 in original plan | **Closed (PR #34).** Verified via two Bun.spawn subprocesses each calling saveIndex with distinct accounts; final accounts.json is valid and contains the last writer's content. ## Test runtime

Bun cold start: ~2.9s for 233 tests. Hot loop (`bun test --watch`) sub-200ms incremental. The original "under 2s" target is missed by ~1s due to Keychain integration tests (`cli.test.ts` revoke flow round-trips via real macOS Keychain with try/finally cleanup). Acceptable trade-off — the alternative was full DI plumbing that would have leaked into production code.
